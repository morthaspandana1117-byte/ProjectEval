# ProjectEval — College Project Evaluation & Voting System

React + Vite + Tailwind CSS frontend (`client/`) and Express + Mongoose API (`server/`) on MongoDB Atlas.

## Features

- **Roles:** Admin, Student, Faculty. Self-registration always creates a *student*; faculty accounts are created by an admin; admin accounts only via the seed script. No API lets a user choose their own role.
- **Attendance-gated voting:** students vote only when marked **Present** for the active session; faculty vote whenever voting is open; admins never vote.
- **Projects:** unique project number, title, abstract, description, technologies, team members, faculty guide and up to 5 supporting files (PDF/PNG/JPG/WEBP/DOCX/PPTX, 5 MB each). Admin approval required before a project is visible or rateable. Presenters cannot rate their own project.
- **Ratings:** 1–5 stars plus required written feedback (20+ characters). One rating per voter per project (unique index); resubmitting updates it.
- **Leaderboards:** separate Student and Faculty leaderboards, each computed only from that group's ratings, with average, vote count, distribution and tie-aware ranks. Admin can hide results until publication.
- **Admin:** dashboard with participation and attendance statistics, account management, attendance marking (bulk), project review, voting & participation reports, Excel exports (attendance per session / all sessions, voting report), event settings, audit log.
- **Privacy:** voter identities are exposed only through admin-only endpoints. Presenters and guides see anonymous feedback.

## Security summary

bcrypt (12 rounds) password hashing · JWT in an `httpOnly` cookie (`SameSite=Lax`, `Secure` in production) with server-side revocation on password change / deactivation / role change · server-side role checks on every route · strict zod validation (unknown fields rejected) · helmet · rate limiting (global, login, registration, writes, uploads) · uploads validated by extension **and** file signature, stored in MongoDB GridFS, served as attachments with `nosniff` and a sandbox CSP · unique indexes on email, roll number, employee ID, project number and (project, voter).

## Local development

Requirements: Node 20+.

```bash
# API
cd server
npm install
cp .env.example .env        # then fill in MONGODB_URI and JWT_SECRET
npm run seed:admin          # needs ADMIN_EMAIL / ADMIN_PASSWORD (see below)
npm run dev                 # http://localhost:5000

# Frontend (second terminal)
cd client
npm install
npm run dev                 # http://localhost:5173 — /api is proxied to :5000
```

Creating the Super Admin: add `ADMIN_NAME`, `ADMIN_EMAIL` and `ADMIN_PASSWORD` to `server/.env` (see `server/.env.example`), then:

```bash
cd server
npm run seed:admin                              # safe to re-run; never duplicates or resets
npm run seed:admin -- --reset-password          # deliberately change the admin password
```

Admin accounts can only be created by this script. The API and the registration page can create only students (public) or students and faculty (admins).

### Checks

```bash
cd server && npm test        # integration tests against an in-memory MongoDB (never touches Atlas)
cd client && npm run lint && npm run build
```

`npm run demo` (in `server/`) starts a throwaway API on port 5055 with sample users (password `Passw0rd!`): `admin@demo.edu`, `meera@demo.edu` (faculty), `asha@demo.edu`, `ravi@demo.edu`. Point the frontend at it with `VITE_PROXY_TARGET=http://localhost:5055 npm run dev`.

## Deployment

The frontend calls `/api` on its own domain; Vercel rewrites those requests to Render. Cookies therefore stay first-party, which avoids third-party-cookie blocking.

### 1. MongoDB Atlas
- *Network Access*: Render's free tier has no static outbound IPs, so allow `0.0.0.0/0` (or use a paid Render plan with static IPs).
- Use a database user with read/write access to the `ProjectEval` database only.

### 2. Render (API)
1. Push the repository to GitHub.
2. Render → **New → Blueprint** → select the repo (uses `render.yaml`), or create a Web Service with root directory `server`, build `npm ci --omit=dev`, start `npm start`, health check `/api/health`.
3. Set environment variables: `MONGODB_URI`, `CLIENT_ORIGIN` (your Vercel URL). `JWT_SECRET` is generated by the blueprint.
4. Open the Render **Shell** and run `ADMIN_EMAIL=... ADMIN_PASSWORD=... npm run seed:admin`, or run the seed script locally against the same Atlas database.

### 3. Vercel (frontend)
1. Edit `client/vercel.json` and replace `YOUR-RENDER-SERVICE.onrender.com` with your Render hostname.
2. Vercel → **New Project** → import the repo → **Root Directory: `client`** (framework: Vite).
3. No environment variables are needed when using the rewrite.

Note: Render free instances sleep after inactivity; the first request can take ~30–60 s. Use a paid instance for the event day.

## API overview

| Area | Endpoints |
|---|---|
| Auth | `POST /api/auth/register` · `POST /api/auth/login` · `POST /api/auth/logout` · `GET /api/auth/me` · `PATCH /api/auth/password` |
| Projects | `GET /api/projects` · `GET /api/projects/mine` · `GET /api/projects/technologies` · `GET/PATCH/DELETE /api/projects/:id` · `POST /api/projects` · `POST /api/projects/:id/files` · `GET/DELETE /api/projects/:id/files/:fileId` · `GET /api/projects/:id/feedback` · `PUT /api/projects/:id/rating` |
| Shared | `GET /api/leaderboard?group=student\|faculty` · `GET /api/faculty` · `GET /api/ratings/mine` |
| Admin | `GET /api/admin/stats` · `/api/admin/users` (CRUD, reset password) · `/api/admin/attendance` (list, bulk mark, sessions, export) · `PATCH /api/admin/projects/:id/status` · `GET /api/admin/projects/:id/ratings` · `/api/admin/reports/voting[/export]` · `/api/admin/reports/participation` · `GET/PATCH /api/admin/settings` · `GET /api/admin/audit-logs` |
